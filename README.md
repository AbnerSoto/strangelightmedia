# Strange Light Media

A portfolio site built with [Astro](https://astro.build), duplicated from an
existing production site's framework as a starting point for a new design.

Modeled on the information architecture and interaction pattern of
high-end photography/multimedia portfolios: category galleries, an
animated homepage mosaic that cycles across every category (photos and
video alike), a lightbox viewer with keyboard/swipe navigation, and a
simple about/contact — with e-commerce, client proofing, and CMS admin
tooling intentionally left out. Content is hand-edited in the repo;
there's no admin UI.

> **Status:** framework complete, content is placeholder. Categories,
> images, copy, logo, and favicon in this repo are all stand-ins —
> see "Replacing the placeholder content" below. Real design files are
> still to come.

## Getting started

```sh
npm install
npm run dev
```

Other scripts:

```sh
npm run build         # production build to dist/
npm run preview       # preview the production build locally
npx astro check       # type-check .astro files and the content schema
npm run placeholders  # regenerate placeholder gallery images (see below)
```

Optional integrations from the site this was duplicated from (Google
Analytics, reCAPTCHA, a real contact-form backend, a custom domain) were
intentionally left out of this scaffold — add them back when they're
needed, each gated behind its own env var the same way.

## Project structure

```
src/
  content.config.ts        # 'galleries' content collection schema (photo or video)
  content/galleries/       # one folder per category; each item is a co-located
                            # markdown file + image (see below)
  data/categories.json     # category slugs/labels/order — drives /work routes
  lib/galleryMedia.ts      # shared photo/video helpers (aspect ratio, thumbnails,
                            # lightbox slides) used across components and pages
  components/              # Nav, Footer, Seo, MasonryGrid, GalleryCard,
                            # MosaicTile (animated homepage grid), Lightbox
  layouts/BaseLayout.astro # <head>, Nav, Footer, global.css, view transitions
  pages/
    index.astro             # home: kinetic hero background + animated mosaic
    work/index.astro        # category index
    work/[category].astro   # one gallery page per category
    about.astro
    contact.astro
  styles/global.css        # color/type/spacing tokens, masonry utility
scripts/generate-placeholders.mjs  # throwaway placeholder-image generator
```

## Content model

Each gallery photo is a markdown file sitting next to its image, e.g.:

```
src/content/galleries/portraits/001-placeholder.jpg
src/content/galleries/portraits/001-placeholder.md
```

```yaml
---
title: "Portraits 1"
category: "portraits"
order: 1
alt: "Describe the image for screen readers and SEO"
featured: false   # true pulls it into the homepage teaser
image: ./001-placeholder.jpg
---
```

A video entry skips `image` and sets `vimeoId` plus a remote `thumbnail`
URL instead — see `src/content.config.ts` and `src/lib/galleryMedia.ts`.

To add a photo: drop the image file and a matching `.md` file into the
right category folder. To add a whole new category: create the folder and
add an entry to `src/data/categories.json`.

## Replacing the placeholder content

Everything under `src/content/galleries/` right now was generated by
`scripts/generate-placeholders.mjs` — solid-color rectangles standing in
for real photos so the routing, masonry grid, and lightbox could be built
and tested end-to-end. Once real photography and the new design are ready:

1. Delete the placeholder `.jpg`/`.md` pairs (or a whole category folder)
   and add real ones following the content model above.
2. Delete `scripts/generate-placeholders.mjs` and the `placeholders` npm
   script — they're one-off scaffolding tools, not part of the site.
3. Replace the bio copy in `src/pages/about.astro` and swap its headshot
   image (`src/assets/about-headshot.jpg`) for a real one.
4. Replace `public/favicon.svg`, `public/favicon-32.png`, and
   `public/apple-touch-icon.png` with the real brand mark, and swap the
   plain-text logo in `src/components/Nav.astro` for a real logo once one
   exists.
5. Decide how `src/pages/contact.astro`'s form should actually submit
   (Formspree, Netlify Forms, or a plain `mailto:`) — it currently posts
   nowhere (`action="#"`, marked with a `TODO`).
6. Swap the palette/type tokens in `src/styles/global.css` for the real
   design direction once design files are available.
7. Once a real domain is ready, update `site`/`base` in
   `astro.config.mjs` and add a `public/CNAME` file.
